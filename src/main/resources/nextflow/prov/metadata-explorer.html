How to use this explorer

  1. Use Browse entities in the left sidebar to search the complete @graph. Type filters and run input/output filters can be combined.
  2. Select an entity to see its incoming and outgoing connections in the Connection map. The inspector on the right preserves its properties, commands, parameters and original JSON.
  3. Use the history buttons or Crate root to navigate entity details. All relationships shows exact property paths for the selected entity.
  4. Use Analyze the run for views organized around execution rather than individual metadata entities.

Analyze the run

  • Workflow DAG: process-level workflow structure with task drill-down.
  • Output lineage: the recorded ancestry of a selected output. The default groups tasks by process; task, scalar-value and software detail can be enabled.
  • Resources: native task trace metrics, grouped by process, with task-level filtering.
  • Software & commands: tools used by recorded tasks and embedded task scripts when evidence capture made them available.

Reuse this page

Open this HTML directly in a browser. Use "Load another crate" or drop an RO-Crate metadata JSON file onto the page. It is processed locally; nothing is sent to a service. Array and ID-keyed-object forms of @graph are accepted.

After loading a different crate, "Save portable page" embeds it in a new self-contained HTML download. Reopening that saved page restores the embedded data. Loading a file alone does not overwrite this page or the metadata on disk.

Interpretation and scope

"Workflow DAG" groups observed tasks by their recorded process orchestration, not by stripping sample names. Solid edges are data relationships; dashed edges are channel dependencies recorded by Nextflow. Disconnected processes remain visible. A process graph can contain cycles after grouping repeated executions; these are identified rather than discarded.

"Output lineage" defaults to a process-level overview: repeated task executions are grouped, intermediate files remain visible, and upstream boundaries are listed explicitly. The task detail mode expands the same path to individual executions. Software and scalar values are optional diagram layers. This is task-level provenance: all declared inputs of a producing task are shown, not proof that each input contributed bytes to a particular output. Scalar values are not matched across tasks by equality. Directory members and dependencies absent from the crate cannot be reconstructed.

"Resources" uses numeric trace metrics embedded by nf-prov-jds with preview or evidence enabled. It does not import the separate Nextflow HTML report or require a trace file. Older crates remain navigable but cannot supply missing measurements. Failed attempts are included when present; cached measurements are optional and excluded from totals by default. Runtimes are summed task runtimes, not workflow wall time; peaks are maxima, not simultaneous memory usage. CPU allocation usage is the unweighted mean of per-task CPU percentages divided by requested cores.

"Software & commands" gathers software entities from recorded task instruments and lists the tasks that used each one. When a tool came from ext.prov.tools, its recorded version, URL, authors, format, keywords and description are shown alongside the task command. Expanded task scripts are shown there when evidence capture embedded them; the entity details panel remains the complete view of the original metadata.

File access and external references

Only HTTP(S) links and safe crate-relative content paths are clickable. A relative path assumes this page is beside the loaded crate's metadata. A saved page must be placed beside the corresponding crate to retain working relative file links. A browser file picker does not grant this page access to the rest of that crate.

Original-machine localPath values are displayed, not treated as packaged files. An HTTP(S) link is opened only when you click it. References without an entity definition remain browsable and are labeled "Reference only"; their metadata is not fetched.

Scope

This is a structural JSON navigator, not a JSON-LD expansion engine or RO-Crate schema validator. Explicit objects containing @id and strings in context-declared ID properties are indexed. Types and literal text are not converted into invented edges. Multi-valued and nested references are preserved.

This explorer does not assess AI readiness, repair missing provenance, verify checksums or confirm that a linked file exists. External dependencies, scalar values absent from the source, and directory children without metadata cannot be reconstructed here.
