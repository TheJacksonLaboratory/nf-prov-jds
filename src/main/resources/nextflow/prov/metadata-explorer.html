A map of the metadata, not just one output

Every entity in @graph is available in the left-hand list. No workflow steps, schemas, configuration files or sibling outputs are discarded. The map shows one entity's neighborhood at a time to keep it readable.

  1. Search for a filename, tool, process, identifier or value. Type filters and root input/output filters can be combined.
  2. Select an entity. Sources referencing it appear on the left; its targets appear on the right. Relationship groups show five entries initially; use "Show all" for the rest.
  3. Click a neighbor to follow the graph. Use the arrows to retrace your steps, or "Crate root" to start over.
  4. The details panel preserves all properties, commands, parameters and original JSON values. "All relationships" includes nested references and their exact paths.

Reuse this page

Open this HTML directly in a browser. Use "Load another crate" or drop an RO-Crate metadata JSON file onto the page. It is processed locally; nothing is sent to a service. Array and ID-keyed-object forms of @graph are accepted.

After loading a different crate, "Save portable page" embeds it in a new self-contained HTML download. Reopening that saved page restores the embedded data. Loading a file alone does not overwrite this page or the metadata on disk.

File access and external references

Only HTTP(S) links and safe crate-relative content paths are clickable. A relative path assumes this page is beside the loaded crate's metadata. A saved page must be placed beside the corresponding crate to retain working relative file links. A browser file picker does not grant this page access to the rest of that crate.

Original-machine localPath values are displayed, not treated as packaged files. An HTTP(S) link is opened only when you click it. References without an entity definition remain browsable and are labeled "Reference only"; their metadata is not fetched.

Scope

This is a structural JSON navigator, not a JSON-LD expansion engine or RO-Crate schema validator. Explicit objects containing @id and strings in context-declared ID properties are indexed. Types and literal text are not converted into invented edges. Multi-valued and nested references are preserved.

This explorer does not assess AI readiness, repair missing provenance, verify checksums or confirm that a linked file exists. External dependencies, scalar values absent from the source, and directory children without metadata cannot be reconstructed here.
